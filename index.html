    James Dyer: Org Speed Keys: Making t Land After the TODO Keyword
    org-use-speed-commands all the time when navigating and performing actions on org headlines, but I think I have found a friction point, something that just feels a little off. When the point is on * and then you press the key t, it calls org-todo via org-self-insert-command. Fast, but the feel is off, the point stays on the stars, so I have to move right before I can type the headline. The reason is in org-todo itself. It has a cursor fixup that parks point just after the keyword, but only when point is not at beginning of line. Speed keys by definition run at beginning of line (org-speed-command-activate requires (bolp)), so the fixup never fires for exactly the keys that would benefit most. There is no custom option for it, so I added a small :after advice: (defun my/org-todo-stop-after-keyword (&rest _) "Move point to just after TODO keyword when `org-todo' leaves it at BOL. (when (and (bolp) (org-at-heading-p)) (when (looking-at org-todo-line-regexp) (goto-char (or (match-end 2) (match-end 1))) (when (looking-at " ") (forward-char 1))))) (advice-add 'org-todo :after #'my/org-todo-stop-after-keyword) * Test with point on * plus t becomes * TODO Test with point on Test, ready to type.
