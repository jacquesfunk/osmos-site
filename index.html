    James Dyer: Two Kinds of Auto-Save in Emacs: Giving Up on the Perfect Save Key!
    Here are the options for a built in automatic saving, so maybe I don't have to focus on any keybindings at all, but can I get used to it? auto-save-mode is on by default in file-visiting buffers. It writes #file# beside the real file (TRAMP copies go to /tmp) after either 300 input events or 30 seconds of idle time. The original is untouched. It runs auto-save-hook but not before-save-hook or after-save-hook, so no formatter, VC refresh, or file watcher fires. Saving normally deletes #file#; after a crash, M-x recover-file or M-x recover-session gets it back. It is the only one of the two that protects a long continuous typing burst. auto-save-visited-mode (Emacs 26.1+) is global and off by default. After five seconds of idle it calls save-some-buffers with no prompt and writes the real files. It runs the full save hooks, VC refreshes, backups, and watchers, and can create a file you were only testing. It also saves every modified file buffer, not just the current one, unless you narrow it with auto-save-visited-predicate (Emacs 29.1+), a buffer-local nil, or remote-file-name-inhibit-auto-save-visited for TRAMP. (setq auto-save-visited-interval 5) (setq remote-file-name-inhibit-auto-save-visited t) (setq auto-save-visited-predicate (lambda () (and (derived-mode-p 'org-mode) (not (file-remote-p buffer-file-name))))) (auto-save-visited-mode 1) auto-save-mode at its defaults and adding visited mode narrowly. Then I will live with it and see: does five seconds feel right?, do the hooks and VC refreshes annoy me?, does it save something I meant to discard?, and do I stop thinking about the save key (is this something I really want?)? If yes, the experiment wins. If not, I will know which side effects actually matter. I will still save deliberately before a commit or a risky change. Auto-save is a safety net, not a save point. Info reader is a “local first” system, where all documentation is stored locally. The source format of the documentation is Texinfo which is exported to different formats, among them Info (used by the Emacs Info reader), HTML, and PDF. Texinfo exported HTML is typically hosted on a website (usually GNU Project), with each Info node mapped to a URL path and indexed by most major search engine services. Discovery of information in Texinfo documentation is frequently done via web search. If the user desires to view that Texinfo web page in the Emacs Info reader, that has to be done manually by corresponding the web page to its Info node. This utility is designed for Emacs users on macOS who also use the Safari web browser. It requires the installation of a macOS Shortcut which is run from the main menu bar.
